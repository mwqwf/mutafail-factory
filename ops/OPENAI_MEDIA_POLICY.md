## القرار التنفيذي

1. الصور: `image_gen.imagegen` المدمج هو المصدر الأول. يثبت `image_sources.json`
   الملف والبصمة وبصمة المطالبة والمراجعة البصرية لكل صورة. يبقى `imgdl3.py`
   موجوداً لكنه مقفل حتى يثبت تعذر OpenAI النهائي وفق الحارس الحالي.
2. الصوت: OpenAI هو المصدر الأول المطلوب، لكن لا يجوز وصفه بأنه متاح لمجرد وجود
   نموذج في وثائق API. يلزم واحد من اثنين: أداة صوت مدمجة قابلة للاستدعاء داخل
   الجلسة، أو تفويض منفصل واضح لتكلفة API وسر محفوظ في GitHub Actions. لا يوجد أيٌّ
   منهما في فحص 2026-09-17، لذلك لا يُكتب سر ولا يبدأ API مدفوع تلقائياً.
3. الاحتياط الصوتي: لا يفتح بسبب timeout أو محاولة واحدة. يفتح فقط بسجل قدرة عام
   خالٍ من الأسرار يثبت غياب أداة الصوت المدمجة وعدم وجود مسار OpenAI مأذون، ويربط
   ذلك باسم الأمر ووقت الفحص. يبقى فحص الاستماع والتحكيم واجبين مهما كان المولّد.

## النماذج الموثقة وقت الفحص

- الصور: `gpt-image-2.5-sunburst` هو الأكثر قدرة في فهرس نماذج OpenAI.
- الكلام: `gpt-4o-mini-tts` مخصص لتحويل النص إلى كلام؛ وتوجد نماذج صوتية أحدث
  للمحادثة الصوتية، لكنها ليست بديلاً تلقائياً لمسار ملفات TTS الطويلة قبل اختبار
  العربية والتشكيل والتجزئة والبصمات.
- الفيديو: توثق OpenAI واجهة توليد فيديو، لكنها خدمة API ذات تكلفة وليست أداة
  مدمجة متاحة في هذه الجلسة. لذلك لا تُستعمل بلا تفويض مالي مستقل.

## الحركة المجانية المعتمدة — قاعدة دائمة لكل الأفلام

المصنع يملك بالفعل `Depth-Anything-V2-Small` محلياً و`kb3d.py` وFFmpeg. المسار
الافتراضي هو: صورة OpenAI معتمدة → خريطة عمق محلية → parallax/حركة كاميرا → طبقات
خرائط وعناوين منشأة برمجياً → شعار → فحص بصري. الكتابة لا تُطلب من نموذج الصور؛
تُرسم لاحقاً من نص موثق، مع اختبار حدود الشاشة والتباين. لا موسيقى.

لا يقتصر ذلك على فيلم بعينه: كل أمر إنتاج جديد يجب أن يضع خطة حركة لكل لقطة. وإذا
ذكر السيناريو مكاناً أو طريقاً أو هجرةً أو توسعاً أو انتقالاً، وجب إدراج خريطة متحركة
موثقة المصدر بدلاً من صورة خريطة ساكنة. اللقطة التي لا تحتاج خريطة تبقى متحركة بعمق
أو حركة كاميرا هادئة. ويمنع النشر إذا بقيت لقطة ثابتة ممتدة بلا تعليل بصري.
